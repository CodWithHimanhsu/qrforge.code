# QRForge: Local QR Studio

**Generate freely. Scan confidently. Own your codes.**

QRForge is a small web app that runs **on your own computer** and creates **static QR codes** as PNG or SVG files. The QR codes are made by Python (the `qrcode` library plus Pillow). There is no account, subscription, quota, watermark, database, or third-party QR service.

- No per-code charges, no generation limit (each code is limited only by the QR standard's capacity)
- Works offline after installation
- Run locally (content never leaves your computer; server listens on `127.0.0.1` only), **or** publish it free on Render behind a password (section 8)
- Types: Website, Text, Wi-Fi, Contact (vCard), Email, Phone, SMS

---

## 1. Static vs. dynamic QR codes (please read)

QRForge makes **static** codes. The code *contains* your data (the URL, the Wi-Fi details, the contact card). Therefore:

- It never expires and has no scan limit, and it keeps working even if QRForge is deleted.
- **You cannot change the destination after printing.** To fix a typo or move a page, you must make a new code.

Services that sell "editable" or "trackable" codes use **dynamic** codes: the code holds a short link to *their* server, which redirects to your real page. That needs an always-online server, which is why they charge subscriptions and why those codes stop working when you stop paying. QRForge deliberately does not offer dynamic codes. If you need one, you must run your own redirect service.

## 2. Setup: Windows

**Step 1. Install Python.** Download Python 3.10 or newer from <https://www.python.org/downloads/>. On the first installer screen, tick **"Add python.exe to PATH"**, then click Install. Check it worked: open **PowerShell** and run

```powershell
python --version
```

It should print `Python 3.10` or higher (3.12 was used for testing).

**Step 2. Open the project folder in a terminal.** In File Explorer, open the `qrforge` folder, click the address bar, type `powershell`, and press Enter. (Or run `cd C:\path\to\qrforge`.)

**Step 3. Create a virtual environment** (a private folder for this project's libraries):

```powershell
python -m venv .venv
```

**Step 4. Activate it:**

```powershell
.venv\Scripts\Activate.ps1
```

If PowerShell says scripts are disabled, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` and try again. In **Command Prompt** use `.venv\Scripts\activate.bat` instead. You should now see `(.venv)` at the start of the line.

**Step 5. Install dependencies** (needs internet, once):

```powershell
pip install -r requirements.txt
```

**Step 6. Start QRForge:**

```powershell
python app.py
```

**Step 7. Open it** in your browser: <http://127.0.0.1:5000>

**Step 8. Stop it:** click the terminal and press **Ctrl+C**. To use it again later, repeat Steps 2, 4 and 6 (not 3 and 5).

## 3. Setup: macOS / Linux

```bash
cd qrforge
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py            # then open http://127.0.0.1:5000 ; stop with Ctrl+C
```

To use another port: `QRFORGE_PORT=8080 python app.py` (macOS/Linux) or `$env:QRFORGE_PORT=8080; python app.py` (PowerShell).

## 4. Using QRForge

1. Choose what to encode (Website, Text, Wi-Fi, Contact, Email, Phone / SMS).
2. Fill in the fields. For websites, the exact address that will be encoded is shown under the box.
3. Optionally pick a preset (**Balanced**, **Print**, **Extra robust**) or change settings. Presets just fill in the controls; they are starting points, not certifications.
4. Click **Generate QR code**, check the preview, then **Download**. **Copy encoded data** copies the text stored in the code (not the image).

Settings: PNG or SVG, PNG size (512/1024/2048 px), error correction L/M/Q/H, code and background colors, quiet zone (4, 6 or 8 modules; **4 is the enforced minimum**).

If you change anything after generating, the preview is marked out of date until you generate again.

### Reliability behavior

- Standard square modules, black on white by default. No logos, dots, gradients, or transparency.
- PNGs use whole-pixel module scaling with nearest-neighbour resizing (only the two chosen colors appear, no blur). If the requested size is not an exact multiple, extra background-colored padding is added, which only enlarges the quiet zone.
- SVGs are real vector paths generated by the library's SVG support (not renamed PNGs).
- Low contrast, light-on-dark ("inverted") colors, and dense symbols (QR version 10+) produce warnings. These are estimates, not guarantees.
- Content that does not fit returns a clear "too large" message; nothing is ever truncated.

### Known format notes

- **Wi-Fi:** `WIFI:T:<WPA|WEP|nopass>;S:<ssid>;P:<password>;H:true;;` with `\ ; , : "` escaped. SSIDs/passwords consisting only of an even number of hex digits are wrapped in double quotes (the ZXing convention) so they are not read as raw hex.
- **Contact:** vCard **3.0** (RFC 2426), CRLF line endings, not line-folded (to keep the code small; mainstream phone scanners accept this).
- **Email:** RFC 6068 `mailto:` with percent-encoding. **Phone:** `tel:`. **SMS:** RFC 5724 `sms:...?body=`. What happens after scanning depends on the scanner and phone; SMS codes normally open a draft the person must send.
- **Non-English text:** stored as UTF-8 bytes. Current phone scanners read this correctly, but a few older scanner apps may misread accented or non-Latin characters in a QR code that lacks an explicit encoding marker. Always test-scan important codes with the scanners your audience uses.

## 5. Tests

```bash
python -m unittest discover -s tests -v
```

The tests use Flask's test client and check real output: PNG files are opened with Pillow (size, only-two-colors, blank quiet zone, uniform module blocks), SVGs are parsed as XML, and Wi-Fi/vCard/mailto/tel/sms payloads are compared against exact expected strings. They also cover error cases (bad JSON, bad colors, sizes, formats, quiet zone, Wi-Fi input, capacity overflow, oversized requests), that no traceback or file path reaches a client, that exception messages never reach the log, that nothing is written to disk, and that 60 consecutive generations all succeed (no quota).

Optional independent decoding: if `opencv-python-headless` is installed (`pip install opencv-python-headless`), an extra test decodes generated PNGs with OpenCV and compares them to the intended payload. It is **not** a project dependency and is skipped otherwise.

Duplicate-submission prevention is frontend behavior (a busy flag in `app.js` ignores a second submit while one is in flight); it is covered by the manual checklist below, not by the Python tests.

Unit tests do not prove that every physical scanner will read every code. Use the checklist.

## 6. Manual QA checklist

- [ ] Chrome or Edge on desktop: generate each content type (Website, Text, Wi-Fi, Contact, Email, Phone, SMS)
- [ ] A phone browser (open `http://<your-computer-ip>:5000` only if you deliberately changed the host; otherwise test the layout with the desktop browser's device mode): layout stacks, no sideways scrolling, buttons are easy to tap, Generate stays reachable
- [ ] PNG at 512, 1024 and 2048: downloads, opens in an image viewer, edges are sharp when zoomed
- [ ] SVG: opens in a browser and in a vector tool (Inkscape, Illustrator, Figma); stays sharp when scaled
- [ ] Scan the on-screen preview and the downloaded PNG with at least two scanner apps (the built-in phone camera plus one other)
- [ ] Print an SVG at a realistic size (for example 3 cm and 5 cm) and scan the paper
- [ ] Black on white, then a supported alternate (dark blue on pale yellow); confirm the warning appears for a low-contrast or inverted pair
- [ ] Short URL and a long URL (about 300 characters); confirm the dense-code warning appears for very long content
- [ ] Unicode text: Hindi/Devanagari, accented letters, emoji; compare the scanned text with the input
- [ ] Wi-Fi: join a real network by scanning (WPA, open, and a password containing `;` `:` `,`)
- [ ] Contact: scanning offers to add a contact with name/phone/email correct
- [ ] Over-capacity text (about 5,000 characters): clear message, form input preserved
- [ ] Click Generate rapidly several times: only one request is made, the button shows "Generating…"
- [ ] Edit a field after generating: the preview is marked out of date
- [ ] Copy encoded data: paste into a text editor and confirm it is the exact payload
- [ ] Clear: form and preview reset
- [ ] **Offline:** after installing, disconnect from the internet, start `python app.py`, and repeat a generate + PNG and SVG download
- [ ] Stop the server while the page is open and click Generate: a friendly "could not reach the server" message appears

## 7. Architecture and where to add things

```
app.py           Flask: routes, JSON errors, security headers, login gate (HTTP only)
auth.py          Password comparison, session fingerprint, login-attempt throttle (no Flask)
qr_service.py    QR engine: build symbol, render PNG/SVG in memory (no Flask)
validators.py    Validation, payload builders, color/contrast helpers (no Flask)
templates/       index.html (app), login.html (sign-in), _brand.html (shared header)
static/          css/styles.css, js/app.js, js/login.js (vanilla JS, no external assets)
tests/           test_app.py (QR + API), test_auth.py (password gate, public mode)
render.yaml      Render deployment blueprint
```

Flow: `app.js` collects fields → `POST /api/generate` → `parse_generation_request` (validate + build payload) → `generate_qr` (image bytes) → JSON response → preview/download via a Blob URL.

**API** `POST /api/generate`

```json
{ "type": "url|text|wifi|contact|email|phone|sms",
  "data": { "...fields for that type..." },
  "format": "png|svg", "size": 1024, "error_correction": "M",
  "foreground": "#000000", "background": "#FFFFFF", "border": 4 }
```

`data` fields: url `{url}` · text `{text}` · wifi `{ssid, password, security: WPA|WEP|nopass, hidden}` · contact `{full_name, phone, email, organization, website}` · email `{to, subject, body}` · phone `{number}` · sms `{number, message}`.
Success returns `filename, mime_type, format, image_base64, payload, version, modules, error_correction, pixel_size, quiet_zone, warnings`. Errors return `{"error": {"code", "message", "field"?}}` with HTTP 400 (invalid input), 413 (too large), or 500 (unexpected, sanitized).

**Adding things later**
- *New content type:* add a `build_xxx_payload` in `validators.py`, register it in `CONTENT_TYPES`/`build_payload`, add a filename label in `app.py`, then a form section in `index.html` and a case in `collectRequest`/`validateClient` in `app.js`.
- *Batch/CSV/ZIP:* call `parse_generation_request` and `generate_qr` in a loop from a new route; the engine needs no change.
- *Logos or decorative styling:* extend `RenderOptions` and the renderers in `qr_service.py`, behind an opt-in advanced mode and with scan testing.
- *Local history:* intentionally left out of v1. If added, keep it in `localStorage`, never store Wi-Fi passwords or contact data, and provide Clear History.

## 8. Publishing online for free (Render) with a password

GitHub Pages cannot run this app (it only serves static files and QRForge needs Python). Render's free web service can. The steps below follow Render's standard Flask flow; check Render's current free-tier terms before relying on them.

### How the password gate works

- Set the environment variable **`QRFORGE_PASSWORD`** and the whole app is locked. Without it (the default when you run locally), there is no password.
- **The password is never stored in the code.** If your repository is public, anything in it is public. Put the password only in Render's dashboard (or your own shell).
- Visitors who are not signed in see only a sign-in page. The QR page and `/api/generate` refuse them (HTTP 401) on the server, not just in the browser.
- After a correct password the server sets a signed, `HttpOnly`, `Secure`, `SameSite=Lax` cookie valid for 30 days. Changing `QRFORGE_PASSWORD` signs everyone out.
- **Remember on this device** (ticked by default): the password is saved in the browser's `localStorage`, filled into the field next visit, and used to sign in automatically. A **Sign out** button clears it. Trade-off: anyone who can use that browser profile can read a saved password, so untick the box on shared computers. If the saved password stops working (you changed it), it is discarded and you are asked for the new one. The sign-in form also uses standard password-field attributes, so your browser's own password manager can offer to save it too.
- Wrong passwords are limited: **5 failures per address in 15 minutes**, then that address is refused for the rest of the window (HTTP 429). The limiter lives in memory, so it resets when the service restarts or sleeps; this is a speed bump against guessing, not a substitute for a strong password.

### Deploy steps

1. Push the project to a GitHub repository (the `.gitignore` already excludes `.venv`).
2. Create a Render account at render.com and connect GitHub.
3. Easiest: choose **New → Blueprint**, pick the repo, and Render reads `render.yaml`. It will ask for **`QRFORGE_PASSWORD`** (enter your password; no quotes needed) and will generate **`QRFORGE_SECRET_KEY`** itself.
   Manual alternative: **New → Web Service** with Build command `pip install -r requirements.txt`, Start command `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 4`, Instance type **Free**, and these environment variables: `QRFORGE_PUBLIC=1`, `QRFORGE_PASSWORD=<your password>`, `QRFORGE_SECRET_KEY=<any long random string>`, `PYTHON_VERSION=3.12.3`.
4. Wait for the build, then open the `https://<name>.onrender.com` address and sign in.

If `QRFORGE_PUBLIC=1` is set without both the password and the secret key, the app **refuses to start**, so a misconfiguration cannot leave it open.

Free-tier behavior to expect: the service sleeps after about 15 minutes without visits and takes around a minute to wake, so the first visit after a quiet period is slow.

To change the password later: edit `QRFORGE_PASSWORD` in Render's Environment tab and let it redeploy. Everyone, including browsers with the old password saved, will be asked for the new one.

### Trying the gate on your own computer

```powershell
$env:QRFORGE_PASSWORD = 'your password here'   # single quotes, so symbols are not interpreted
python app.py
```
macOS/Linux: `QRFORGE_PASSWORD='your password here' python app.py`. Close the terminal (or remove the variable) to go back to no password.

### What changes about privacy when hosted

Locally, nothing leaves your computer. Hosted, whatever a visitor types (including Wi-Fi passwords and contact details) travels over HTTPS to the server, which builds the image and sends it back. QRForge does not save or log it, but the hosting provider can keep ordinary connection records. The hosted pages say so. For sensitive codes, the local version is the more private option.

## 9. Privacy and security notes

No analytics, ads, accounts, remote logging, CDNs, or external fonts. Strict Content-Security-Policy (`default-src 'self'`). Locally the server binds to `127.0.0.1` with debug off; hosted, gunicorn serves it and `QRFORGE_PUBLIC=1` adds Secure cookies, HSTS, and proxy-aware client addresses. Requests are capped at 128 KB, validated server-side with allowlists, and filenames come from fixed labels. Logs contain only exception class names and stack locations, never payloads, messages, or passwords. There is no database and nothing is written to disk.

Not included: per-user accounts, password reset, or persistent rate limiting. This is a single shared password for a small private audience.
